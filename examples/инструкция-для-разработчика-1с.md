# Инструкция: интеграция 1С УПП с дашбордом продаж

## Что нужно сделать

Настроить автоматическую отправку данных о продажах и планах из 1С УПП
на сервер дашборда раз в час. Дашборд будет обновляться в реальном времени.

---

## Шаг 1 — Создать общий модуль

В конфигураторе:

**Конфигурация → Общие → Общие модули → (правая кнопка) Добавить**

Параметры модуля:
- Имя: `ДашбордПродаж`
- Флаги: ✅ Сервер, ✅ Вызов сервера

Скопировать в модуль содержимое файла:
```
examples/upp-http-export-template.bsl
```

---

## Шаг 2 — Проверить запрос к продажам

В модуле есть функция `ПолучитьПродажи()` — она обращается к:

```
РегистрНакопления.Продажи.Обороты(...)
```

Поля которые используются:
| Поле в запросе | Что это |
|---|---|
| `Прод.Склад.Код` | Код склада (точка продаж) |
| `Прод.Склад.Наименование` | Название склада |
| `Прод.Номенклатура.Код` | Код товара |
| `Прод.Номенклатура.Наименование` | Название товара |
| `Прод.Номенклатура.НоменклатурнаяГруппа.Наименование` | Категория товара |
| `Прод.КоличествоОборот` | Количество |
| `Прод.ВыручкаОборот` | Выручка (сумма со скидкой) |
| `Прод.СебестоимостьОборот` | Себестоимость |

Проверить в консоли запросов что регистр и поля существуют в данной конфигурации.

## Шаг 2.0 — Проверить запрос к розничным продажам ⚠️ КРИТИЧНО

В модуле есть функция `ПолучитьРозничныеПродажи()` — она обращается к:

```
РегистрНакопления.РозничныеПродажи.Обороты(...)
```

**Зачем этот запрос:** `РегистрНакопления.Продажи.ВыручкаОборот` — это «грязная»
сумма (стоимость позиций по прайсу), без учёта скидок и без списания бонусов.
Поэтому факт на дашборде завышен. Чистую сумму, которую клиент реально
заплатил, нужно брать из `РегистрНакопления.РозничныеПродажи.СуммаОборот`.

Поля которые используются:
| Поле в запросе | Что это |
|---|---|
| `РП.Склад.Код` | Код склада (точка продаж) |
| `РП.Номенклатура.Код` | Код товара |
| `РП.СуммаОборот` | Сумма по чеку с учётом скидок |
| `РП.КоличествоОборот` | Количество |

**Что нужно проверить:**

1. **Есть ли регистр** `РегистрНакопления.РозничныеПродажи` в данной конфигурации.
   Если регистра нет — функция перехватит исключение и вернёт пустую таблицу
   (дашборд продолжит работать с «грязной» суммой из `Продажи.ВыручкаОборот`).

2. **Имена ресурсов**: в типовой УПП розница — `СуммаОборот`. В кастомных
   могут называться `СуммаПродажиОборот`, `СуммаДокументаОборот` и т. п.
   Если запрос падает или возвращает пусто — поправить имена.

3. **Включает ли `СуммаОборот` списание бонусов**. В типовой УПП — да,
   потому что в чеке ККМ списание бонусов уменьшает сумму к оплате.
   Но если в данной конфигурации бонусы лежат отдельно
   в `РегистрНакопления.БонусныеБаллы.СписаниеОборот` — их нужно
   дополнительно вычесть из суммы.

4. **Сверить итоги** за прошлый месяц: запустить запрос за закрытый период
   и сравнить с отчётом «Анализ розничных продаж» в самой 1С — суммы
   должны совпасть копейка в копейку.

## Шаг 2.1 — Проверить запрос к валовой прибыли ⚠️ ВАЖНО

В модуле есть функция `ПолучитьВаловуюПрибыль()` — она обращается к:

```
РегистрНакопления.ВаловаяПрибыль.Обороты(...)
```

**Зачем этот запрос:** в типовой УПП себестоимость в `РегистрНакопления.Продажи`
часто = 0 (рассчитывается отдельно при закрытии месяца). Из-за этого маржа
на дашборде получается равной выручке, что неверно. Реальные себестоимость
и валовая прибыль лежат в отдельном регистре `ВаловаяПрибыль`.

Поля которые используются:
| Поле в запросе | Что это |
|---|---|
| `ВП.Подразделение.Код` | Код подразделения (точка продаж) |
| `ВП.Номенклатура.Код` | Код товара |
| `ВП.ВыручкаОборот` | Выручка |
| `ВП.СтоимостьОборот` | Себестоимость |

Расчёт: `ВаловаяПрибыль = ВыручкаОборот - СтоимостьОборот`.

**Что нужно проверить:**

1. **Есть ли регистр** `РегистрНакопления.ВаловаяПрибыль` в данной конфигурации.
   В типовой УПП 1.3 он есть; в кастомизированных может отсутствовать.
   Если регистра нет — функция перехватит исключение и вернёт пустую таблицу
   (дашборд покажет маржу = 0, продажи продолжат работать).

2. **Имена ресурсов**: в типовой УПП — `ВыручкаОборот` и `СтоимостьОборот`.
   В некоторых конфигурациях могут называться `СуммаВыручкиОборот`,
   `СуммаСебестоимостиОборот` и т. п. Если запрос падает — поправить имена.

3. **Измерение точки продаж**: в типовой УПП регистр индексируется по
   `Подразделение`, а регистр `Продажи` — по `Склад`. Дашборд связывает
   строки по одинаковому коду. Если в конфигурации код подразделения
   не совпадает с кодом склада (для одной и той же точки продаж) —
   замените `ВП.Подразделение.Код` на `ВП.Склад.Код` или на то измерение,
   код которого совпадает со `Склад.Код` из регистра `Продажи`.

4. **Проверить в консоли запросов**, что регистр и поля существуют
   и что выборка не пустая за текущий месяц.

## Шаг 3 — Уточнить источник плана продаж

В модуле есть функция `ПолучитьПланы()` — она обращается к:

```
РегистрНакопления.ПланыПродаж.Обороты(...)
```

**Нужно уточнить**: из какого регистра/документа берётся «Идеальный результат»
в отчёте «Анализ план-факта по магазинам». Это может быть:

- `РегистрНакопления.ПланыПродаж` — стандартный регистр УПП
- `РегистрСведений.ПланыПродажПоМагазинам` — если настраивался вручную
- Другой объект конфигурации

Если регистр называется иначе — поправить запрос в функции `ПолучитьПланы()`.
Если план хранится только по магазинам без разбивки по товарам — адаптировать
запрос и структуру данных (убрать `productId`, оставить только `storeId` и `amount`).

## Шаг 4 — Создать регламентное задание

**Конфигурация → Общие → Регламентные задания → Добавить**

Параметры:
- Имя: `ВыгрузкаВДашбордПродаж`
- Метод: `ДашбордПродаж.ВыполнитьВыгрузкуВДашборд`
- Использование: ✅ включено

Расписание (кнопка «Расписание»):
- Повторять каждые: **3600 секунд** (1 час)
- Или настроить по времени: например каждый день в 07:00, 10:00, 13:00, 16:00, 19:00

## Важно

Тип `URI` в 1С доступен только в мобильном приложении и недоступен на сервере.
В модуле `ОтправитьPOST()` хост и путь прописаны явно — не использовать `Новый URI()`.

---

## Шаг 5 — Проверить подключение вручную

Перед запуском по расписанию — проверить вручную:

1. Открыть **Сервис → Консоль функций** (или любой другой способ запустить код на сервере)
2. Выполнить:
```bsl
ДашбордПродаж.ВыполнитьВыгрузкуВДашборд();
```
3. В окне сообщений должен появиться ответ вида:
```json
{"ok":true,"run":{"status":"success","period":"2026-04",...}}
```

Если ответ `status: "success"` — всё работает, данные ушли на сервер.

## Что происходит после отправки

- Данные сохраняются в PostgreSQL
- Дашборд в браузере обновляется автоматически (без перезагрузки страницы)
- Каждая отправка логируется — можно посмотреть на `/api/ingest/runs`
- Повторная отправка одного и того же пакета безопасна (дедупликация по хэшу)
